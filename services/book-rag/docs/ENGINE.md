# SAMS Library RAG — محرك البحث الذكي (ملفات بايثون)

محرك البحث والإجابة الخاص بفهرس مكتبة SAMS، منقول من النوت بوك `Hybrid_RAG_v12` **بنفس المنطق**.
تم التأكد من التطابق: 16 سؤالاً × 13 مخرجاً، مرة بدون Gemini ومرة مع Gemini وهمي = 416 مقارنة، بلا أي فرق.

## التشغيل

```bash
pip install -r requirements.txt
cp .env.example .env                      # ثم ضع GEMINI_API_KEY
# ضع ملف SAMS_Books_Merged_Book_Names_Corrected.xlsx في مجلد data/

python scripts/ask.py                     # جرّب: كتب أحمد ماهر   ثم   /card 17   ثم   /reset
pytest -q                                 # 95 اختبار (المحرك + الـ API + Streamlit + واجهة الكتاب)
python scripts/evaluate.py                # تقييم البحث والفلاتر ومقارنته بالنوت بوك (بدون Gemini)
```

## قبل أي تعديل على المحرك

```bash
python scripts/evaluate.py                     # 12.1 + 12.2 (دقائق على CPU، بدون Gemini)
python scripts/evaluate.py --generation        # + 12.3 (5 أسئلة لـ Gemini)
python scripts/evaluate.py --triad             # + 12.5 RAG Triad (حوالي 32 طلب لـ Gemini)
python scripts/evaluate.py --all-retrievers    # + جدول كل طرق البحث كما في النوت بوك
```

يقارن النتائج بالأرقام المرجعية v13 (nDCG@10 = 0.897 والأرقام لكل نوع سؤال)، ويكتب **FAIL** إذا نزل أي رقم أكثر من 0.01،
ويحفظ تقريراً في `reports/`. التعديل لا يُعتمد إلا مع **PASS**.
تم التأكد أن هذا السكربت يعطي نفس أسئلة النوت بوك (84) ونفس الأرقام عند نفس النماذج.

بعد أول تشغيل تُحفظ النماذج (نموذج المعنى ونموذج إعادة الترتيب) في `models/` والمتجهات في `rag_store/`، فيعمل التشغيل التالي بدون تنزيل.
بدون مفتاح Gemini (أو `LLM_PROVIDER=extractive`) يعمل كل شيء ما عدا الإجابة المكتوبة: يظهر الرد الاحتياطي (قائمة الكتب والبطاقات).

## الاستخدام من الكود

```python
from sams_rag.engine import ChatSession, serialize, book_card, book_ids_for_code

chat = ChatSession()                       # جلسة لكل باحث
out = chat.ask("كتب أحمد ماهر")
data = serialize(out)                      # dict جاهز لـ JSON: answer, sources (بطاقات 22 حقلاً), all_books, hint ...
card = book_card(book_ids_for_code("1687"))   # بطاقة كتاب بكوده (السجلات المكررة مدموجة)
chat.reset()                               # محادثة جديدة
```

**ملاحظة:** استيراد `sams_rag.engine` يحمّل الفهرس والنماذج والفهارس (ثوانٍ بعد أول تشغيل)، فيُستورد مرة عند تشغيل الخادم.

## الفروق عن النوت بوك (لا تغيّر النتائج)

- حُذف ما يخص النوت بوك فقط: الطباعة والعرض، وتحميل Colab، والتجارب، وأقسام التقييم، وClaude وOllama، والتحليل الصرفي (كان مطفأً).
- `LAST_BOOK_LIST` (متغير عام) → تُعاد مجموعات القائمة في `out["all_books_groups"]`، و`show_card(n)` → `book_card(ids)`.
- `GEMINI_LAST_MODEL` (متغير عام) → قيمة منفصلة لكل طلب (`last_gemini_model()`)، لأن الخادم يخدم أكثر من باحث في الوقت نفسه.
- `print` → `logging` (اسم الـ logger: `sams_rag`).
- نموذج إعادة الترتيب يُحفظ نسخة منه في `models/` ويُحمَّل منها (كما يفعل النوت بوك مع نموذج المعنى).

## توسيع البحث بين اللغتين (v13)

سؤال عن موضوع بلغة (مثل «books about marketing») يبحث أيضاً بمرادفاته في اللغة الأخرى («التسويق») من قاموس صغير
لمجالات المكتبة (`sams_rag/expansion.py`)، كقائمتين إضافيتين في الدمج RRF، والسؤال الأصلي لا يتغير وإعادة الترتيب
تتم عليه. لا يعمل مع أسئلة المؤلفين ولا العناوين. الإعداد `CONFIG["query_expansion"]` (افتراضياً `True`؛ `False` = سلوك v12 بالضبط).

| | v12 | v13 (بالتوسيع) |
| --- | --- | --- |
| nDCG@10 الإجمالي | 0.887 | **0.897** |
| عربي + إنجليزي | 0.749 | **0.813** |
| بالمعنى | 0.764 | **0.782** |
| صيغ عربية مختلفة | 0.843 | **0.858** |
| المؤلفين / العناوين / المواضيع | 0.990 / 1.000 / 0.792 | بلا تغيير |

**اعتُمد (v13 = الرقم المرجعي الجديد 0.897 في `evaluation.py`)** بعد اختباره على 28 سؤالاً جديداً لا علاقة لها بأسئلة
التقييم: أسئلة مواضيع القاموس 0.764 ← 0.883 (+0.119؛ إنجليزي +0.188، عربي +0.073، مختلط +0.086)، وأسئلة المقارنة
(مواضيع خارج القاموس) لم تتغير إطلاقاً. السكربت للتكرار:

```bash
python scripts/holdout_expansion.py    # 28 سؤالاً جديداً: 22 في مواضيع القاموس + 6 للمقارنة (يجب ألا تتغير)
```

## أسئلة «الأحدث» (v14)

«وإيه الأحدث فيهم؟» أو «أحدث كتب التسويق» أو «latest books on marketing»: يأخذ البحث أقرب 20 كتاباً للموضوع
(`CONFIG["recency_pool"]`) ويرتبها من الأحدث للأقدم، وكذلك القائمة الكاملة، ويُطلب من Gemini الالتزام بالترتيب وذكر السنة.
الكتب بلا سنة تأتي في الآخر. الكلمات المستخدمة لا تظهر في عناوين الفهرس (الأحدث، أحدث، الأجدد، آخر الإصدارات،
newest، latest، most recent)؛ «الحديثة» و«الجديدة» و«new» تظهر في عشرات العناوين فلا تُستخدم، والسؤال الذي هو جزء من
عنوان كتاب لا يُعامل كسؤال «الأحدث». لا يتغير شيء في أي سؤال آخر (ولا في أسئلة التقييم الـ84). الرد يحتوي `"recency": true`.

## قائمة كل كتب الموضوع (v15)

«كتب عن التسويق»: الرد المكتوب كما هو (أنسب 5–6 كتب)، والقائمة تحته أصبحت **كل كتب الموضوع** في الفهرس (151 كتاباً
لـ«التسويق» بعد دمج المكرر) بدل «أقرب 30»: أقرب الكتب من البحث أولاً (كما كانت، فلا يختفي كتاب كان يظهر)، ثم باقي
كتب الموضوع من الأحدث للأقدم، مع رسالة «عُرض 5 من أصل 151 كتاباً في موضوع «التسويق»». الموضوع = عنوان موضوع من
الفهرس يذكره السؤال (ويشمل ما يحتويه: «التسويق» يشمل «التسويق الإلكتروني»)؛ وعند عدة مواضيع يُؤخذ الأدق، ومع موضوعين
مختلفين («التسويق في البنوك») الكتب التي تجمع الاثنين. لا يعمل مع أسئلة المؤلفين (قائمتها كاملة أصلاً) ولا العناوين
(«التمويل المعاصر»)، إلا إذا كان السؤال هو اسم الموضوع نفسه. الإعدادان `topic_full_list` (`False` = أقرب 30 كما كان)
و`topic_full_list_max` (400). في الرد: `topic_list` (`headings`، `count`) و`in_topic` لكل كتاب في القائمة. لا يتغير
الرد المكتوب ولا التقييم (الأسئلة الـ84 متطابقة).

## القائمة الكاملة في الموقع وصفحة الكتاب (v16)

كل ما يخص القائمة تحت الرد أصبح في المحرك (`sams_rag/listing.py`)، فيعطي الـ API نفس قائمة صفحة الكتاب:

- **الطول:** أقرب 100 كتاب (`all_books_limit`، كان 30)، ثم تُصفّى: **أول 20 تبقى دائماً** (`BOOK_KEEP_TOP`)، وبعدها
  يبقى الكتاب إذا كانت درجة صلته ≥ 0.2 (`BOOK_MIN_RELEVANCE`) أو إذا كان مذكوراً في الرد. الرقم 20 مقيس
  (`scripts/keep_top_study.py`)، وحد أدنى لأول 20 جُرّب (`scripts/floor_study.py`) ورُفض لأنه يحذف كتباً صحيحة.
- **قائمة الموضوع:** كتب الموضوع كلها تبقى (`in_topic: true`) في أول القائمة، والكتب القريبة فقط تُصفّى. في `all_books`:
  `topic_count` و`related_count` (لزر مثل «كتب الموضوع (16) + 20 كتاباً قريباً»)، و`relevant_only: true`.
- **اسم مؤلف مكتوب بشكل مختلف** («كتب دكتور نفين مكرم»): إذا كانت كل الكتب المذكورة في الرد لمؤلفين يشبه اسمهم كلمة
  في السؤال (80% فأكثر)، تصبح القائمة كل كتب هؤلاء المؤلفين فقط، كسؤال مؤلف مكتوب صحيحاً. في الرد:
  `author_list` (`authors`، `count`) وملاحظة «عُرض 3 من أصل 6 كتب للمؤلفين ...».
- **الكتاب المذكور دون وسمه:** كتاب من مصادر الرد مكتوب بالخط العريض بعنوانه يُضاف إلى `sources` (عنوان من كلمة واحدة
  يجب أن يطابق تماماً).

- **مواضيع اللغة الأخرى في قائمة الموضوع:** الفهرس يسجّل المجال نفسه بعنوان إنجليزي وعنوان عربي («Computer science»
  16 كتاباً، و«الحاسبات الالكترونية» وتفريعاتها 55 كتاباً). إذا كان الموضوع المكتشف مصطلحاً في القاموس (v13)، تُضاف
  الكتب التي **يبدأ** عنوان موضوعها بأحد مرادفاته («Computer Networks»، «الحاسبات الالكترونية - برامج»؛ لا «التسويق -
  تطبيقات الحاسب الآلي»). «computer science»: 16 ← 84، «التفاوض»: 14 ← 34، «الموارد البشرية»: 29 ← 162. في الرد
  `topic_list.synonyms`، والملاحظة تقول «ومرادفاته في الفهرس». الإعداد `topic_synonyms` (`False` = كما كان).
  وسؤال فيه كلمة من القاموس ليست موضوعاً في الفهرس («كتب عن الكمبيوتر») يُعامل كسؤال موضوع إذا كان مرادفها موضوعاً
  («Computer science»)، بشرط مجال واحد فقط في السؤال، ومع نفس حماية أسئلة المؤلفين والعناوين (`topic_from_glossary`).
- **قاعدة 13 لـ Gemini:** إذا سُئل عن مؤلف غير موجود في المصادر وفيها مؤلفون بأسماء قريبة، لا يرفض: يقول بوضوح إن
  الاسم غير موجود في الفهرس ثم يعرض كتب الأسماء القريبة. واختلافات الكتابة (الهمزة، ي/ى، ة/ه، اللقب، الاسم الأول أو
  الأخير وحده) تُعد الاسم نفسه.

لا يتغير البحث ولا التقييم (0.897).

## الخادم (FastAPI)

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
# صفحة التوثيق وتجربة كل المسارات من المتصفح:  http://localhost:8000/docs
```

| المسار | الوظيفة |
| --- | --- |
| `POST /api/ask` | سؤال الباحث: `{"question": "...", "session_id": "...", "filters": {...}}` |
| `GET /api/jobs/{job_id}?wait=10` | متابعة سؤال لم يكتمل رده بعد |
| `GET /api/books/{book_code}` | البطاقة الكاملة (22 حقلاً) لكتاب |
| `POST /api/session/reset` | محادثة جديدة: `{"session_id": "..."}` |
| `GET /api/health` | حالة الخادم والمحرك |

**طريقة الرد على السؤال:**
1. البحث فوري، وGemini يعمل في الخلفية.
2. إذا اكتمل الرد خلال `API_WAIT_S` (10 ثوانٍ، أغلب الأسئلة) يعود مباشرة: `{"status": "done", "result": {...}}`.
3. وإلا تعود الكتب التي وُجدت: `{"status": "pending", "job_id": "...", "message": "...", "preview": {"books": [...]}}`،
   فتعرضها الواجهة كنتائج مبدئية، وتسأل `GET /api/jobs/{job_id}` حتى يصل `done`. عند وصول الرد النهائي تُستبدل النتائج
   المبدئية بما في `result` (قد يستخدم Gemini بعض الكتب فقط، أو يرفض).
4. Gemini لا يعمل أكثر من `API_GEMINI_BUDGET_S` (90 ثانية)؛ بعدها تبقى الكتب مع `"notice": "المساعد مشغول حالياً..."`.
5. أول سؤال في المحادثة يُخزَّن، فالسؤال المكرر يُجاب فوراً بلا Gemini (`"cached": true`). الرد الاحتياطي لا يُخزَّن.

**`result`** = `serialize()` من المحرك: `answer`، `is_refusal`، `hint`، `coverage_note`، `notice`، `sources` (بطاقات 22 حقلاً)،
`all_books` (`complete` + `items`، وفي قائمة الموضوع `topic_count` و`related_count`؛ لكل كتاب `in_answer` و`in_topic`)،
`topic_list`، `author_list`، `recency`، `filters_applied`، `search_query`، `provider`، `model`، `latency_s`.

**أكواد أخرى:** `401` كلمة سر الخدمة ناقصة أو خاطئة · `409` سؤال آخر لنفس المحادثة لم ينتهِ بعد · `429` تجاوز حد الأسئلة · `422` سؤال فارغ أو أطول من 500 حرف.

**الربط مع موقع المكتبة (Express):** ثلاثة headers يرسلها خادم Express مع كل طلب:

| Header | المعنى |
| --- | --- |
| `X-Service-Key` | كلمة سر مشتركة (`API_SERVICE_KEY`). إذا ضُبطت في الإعدادات يُرفض أي طلب بدونها (`401`)؛ `/api/health` يبقى مفتوحاً |
| `X-User-Id` | معرّف المستخدم، فيُحسب حد الأسئلة لكل مستخدم (بدونه يُحسب لكل عنوان IP) |
| `X-User-Role` | أدوار المستخدم مفصولة بفواصل، مثل `STUDENT` أو `LIBRARIAN`. الأدوار في `API_UNLIMITED_ROLES` (افتراضياً `LIBRARIAN`) بلا حد |

في الإنتاج: `API_SERVICE_KEY` = كلمة سر طويلة عشوائية، و`API_ALLOWED_ORIGINS` فارغ (لا طلبات من المتصفح مباشرة).
لتوليد كلمة السر: `python -c "import secrets; print(secrets.token_urlsafe(32))"`.

**التسجيل:** سطر JSON لكل سؤال في `logs/queries.jsonl` (السؤال، والبحث، والنموذج، والزمن، والرفض، والاستشهادات، وأخطاء Gemini)،
ومعرّف المحادثة مشفّر. **الإعدادات:** متغيرات `API_*` في `.env.example`.

**ملاحظة:** المحادثات والتخزين المؤقت في ذاكرة الخادم، فتعمل مع عملية (process) واحدة. عند تشغيل أكثر من عملية تُنقل إلى Redis بنفس الواجهة.

**إضافات في المحرك للموقع (لا تغيّر نتائجه):** `retrieve()` و`finish()` (نفس `rag_answer` على خطوتين، ومختبرة أنها تعطي نفس النتيجة)،
و`ChatSession.begin()` و`end()`، و`preview()`، والإعداد `gemini_time_budget_s` (افتراضياً بلا حد كما في النوت بوك).
