# Dataset update: impact assessment (Project.xlsx v1 -> v2)

Evidence: `docs/DATASET_COMPARISON.md` (generated by `scripts/compare_datasets.py`, keyed by `BOOK_CODE`).
The old file (v1, sha256 `09705d93…3c76`) is **not part of the package** (removed at the owner's request); this document and `DATASET_COMPARISON.md` are the audit record of the v1→v2 comparison. Nothing in the code, tests or scripts references it.
The active source of truth is `data/raw/Project.xlsx` (sha256 `34e2be48…8528`).

## What differs

| | v1 | v2 |
|---|---|---|
| data rows / BOOK_CODEs | 3,983 | 3,983 (identical set, identical order; 0 added, 0 removed) |
| Title, Students, Supervisor, call number, extent, dimension, subjects | | **identical in all 3,983 rows** |
| Column headers | `WORK \| PUBLISHING_DATE`, `WORK \| CALL_NUM`, `WORK \| EXTENT`, `WORK \| DIMENSION`, `SUBJECTS_ALL` | `' PUBLISHING_DATE'`, `' CALL_NUM'`, `' EXTENT'`, `'DIMENSION'`, `'SUBJECTS'` (**5 renamed**; two keep a leading space) |
| Publishing date | 4 implausible years | **4 corrected**: 2419: 2103→2014; 2424: 3014→2014; 2561: 2105→2015; 3683: 3023→2023 |

Processed data (`records.jsonl`) diff between the v1 build and the v2 build: exactly those 4 records changed
(`year` None→value, `year_raw`, `raw`, `year_suspect` flag removed). Nothing else.

## Impact per component

| Component | Class | Evidence / action |
|---|---|---|
| Header handling in loader (`read_raw_rows`), `reconcile.py`, oracle | **3. Code change (genuinely required)** | Exact-name lookup would have missed all 5 renamed columns and **silently** produced records with no year, call number, extent, dimension or subjects. Added `canonical_header()` (accepts both layouts), and the loader now raises a clear error when any required column is absent. Tests: `tests/unit/test_header_aliases.py`, `test_import_accepts_the_renamed_header_layout`. |
| Excel import endpoint (`/admin/import`) | **3. Code change** | Same loader path; now rejects files lacking any of the 9 columns (previously only BOOK_CODE/TITLE were required, so a renamed-column file would import with data loss). |
| Data cleaning / validation | 1. No change | Year rules unchanged; the 4 corrected values pass the existing validation. |
| Database + search index + embeddings | **2. Data reprocessing** | `scripts/bootstrap.py`: incremental sync reported `updated 4, unchanged 3979, created 0, deleted 0`; consistency check clean. Embeddings are recomputed only for changed records by content hash. |
| Year filter / facets | 2. Reprocessing | 4 records now carry a year (valid years 3,969→3,973; missing-year count unchanged at 10). New live check: year filter == independent oracle for all 26 years. |
| Student / supervisor / title / subject / topic search, pagination, normalisation | 1. No change (verified) | Names, titles, supervisors, subjects are byte-identical, so ground truth is unchanged; live check 36/36 and full suite re-run on the v2 data. |
| API auth, RBAC, errors, OpenAPI | 1. No change | Live checks pass; OpenAPI contract test passes. |
| Tests | 3. Added 3 tests; existing tests use synthetic fixtures with their own years, so unaffected. | See TEST_REPORT. |
| Docs / packaging | 3. Updated | Dataset hash, comparison, impact; historical file clearly labelled. |
| Evaluation numbers (retrieval metrics) | 1. Not re-derived by data change | Titles/subjects/supervisors identical; metrics depend on those fields only. |

## Ambiguities left alone
* The 4 corrected years are the team's edit of the source; the service does not guess years itself. Records with other
  implausible years (none remain in v2) would still be flagged `year_suspect`, never auto-corrected.
* Student identity remains name-only (no student id in either version).
