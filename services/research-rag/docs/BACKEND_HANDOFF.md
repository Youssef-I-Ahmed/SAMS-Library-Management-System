# SADAT RAG Backend — Handoff for the academy's software team

Standalone FastAPI service for catalogue search and evidence-grounded Q&A over the academy's projects and research records.
It does **not** need Streamlit (`requirements.txt` no longer lists it; the legacy UI lives in `requirements-ui.txt`).
Verified results are in `docs/BACKEND_TESTING_REPORT.md` — read its "Not verified" section before go-live.

## 1. Quick start (server, no Docker)
```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # then edit: LLM_API_KEY, SERVICE_JWT_SECRET (python -c "import secrets;print(secrets.token_hex(32))")
python scripts/gemini_check.py  # live Gemini verification; must end with exit code 0 (see §3)
python scripts/bootstrap.py     # first run only: imports data/raw/Project.xlsx -> index, reconciles, verifies (3,983 records)
uvicorn api.main:app --host 0.0.0.0 --port 8000 --no-access-log
```
The first start downloads the ~220 MB multilingual ONNX embedding model from huggingface.co once (kept in
`EMBEDDING_MODEL_CACHE_DIR`). If it cannot be downloaded, the service **still starts** in lexical (hashing) mode and says so
in `GET /ready` → `embedding`; semantic/cross-language search is then off. Check this line after every deployment.

Docker: `docker compose up -d --build` (needs `.env`; import the dataset once with `docker compose --profile import run --rm rag-import`).
Interactive documentation: `http://<host>:8000/docs` (Swagger) and `/openapi.json` (copy in `docs/openapi.json`).

## 2. Endpoints (all JSON, UTF-8)
| Method / path | Auth | Purpose |
|---|---|---|
| `GET /health` | none | liveness |
| `GET /ready` | none | database + index + embedding mode + LLM configured? (503 while not ready) |
| `POST /search` | `rag:read` | search with a JSON body (recommended); same engine as `GET /search`, results are identical |
| `GET /search` | `rag:read` | same, with query parameters (kept unchanged) |
| `POST /ask` | `rag:read` | grounded answer; abstains when records cannot support one |
| `GET /records/{id}`, `/supervisors`, `/supervisors/records`, `/students`, `/students/records`, `/facets/*` | `rag:read` | catalogue browsing |
| `/admin/*` | `rag:admin` + role | create/update/delete, import, sync, reindex, audit |

**Authentication:** your backend signs a short-lived (≤ 10 min) HS256 JWT with `SERVICE_JWT_SECRET`
(`iss=sadat-express`, `aud=sadat-rag`, `sub`, `scope="rag:read"` or `"rag:read rag:admin"`, `role`, `iat`, `exp`).
Node example: `docs/INTEGRATION.md` §2. For manual tests: `python scripts/make_token.py [--admin]`.
The browser must never hold `SERVICE_JWT_SECRET`; call the RAG from your server. CORS is off by default (server-to-server);
for browser-direct development set `CORS_ORIGINS=https://your-frontend` (comma separated).

### POST /search
```bash
curl -X POST http://localhost:8000/search -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"q":"التسويق الرقمي","mode":"keyword","year_from":2015,"page":1,"page_size":10}'
```
Body fields: `q`, `mode` (`auto|all|title|supervisor|student|subject|keyword|semantic|hybrid`), `year`, `year_from`, `year_to`, `subject`,
`supervisor`, `supervisor_key`, `student`, `student_key`, `call_number_prefix`, `language` (`ar|en|mixed`),
`sort` (`relevance|year_desc|year_asc|title|record_id`), `page`, `page_size` (≤ `MAX_PAGE_SIZE`, 100), `fuzzy`, `supervisor_match`.
Response (abridged, real output): `{"total":100,"page":1,"page_size":3,"total_pages":34,"exhaustive":false,"strategy":["bm25"],`
`"hits":[{"record_id":"3420","title":"التسويق الرقمى ودوره فى تحقيق سعادة العملاء","year":2021,"call_number":"658.8","subjects":[…],"score":…,"match_type":…}],"notes":[…]}`.
`title/supervisor/student/subject` modes are exhaustive; `keyword/semantic/hybrid` are ranked and say so in `notes`.

### POST /ask
```bash
curl -X POST http://localhost:8000/ask -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"question":"ما هو المشروع رقم 3420؟"}'
```
Response fields: `status` (`ok` = generated by Gemini and verified | `answered_from_catalog` = deterministic answer from the data | `abstained` | `answer_withheld` | `llm_unavailable` | `llm_error` | `error` = technical failure, never to be read as "not in the data"), `answer`, `generated_by` (`llm|catalog|policy|none`), `abstain_reason`
(`no_results` | `insufficient_evidence` | `content_not_available` | `record_not_found` | `empty_question`), `sources[]` (the records used), `total_matching`, `llm` (provider/model/error kind), `warnings`, `limitations`.
Behaviour to rely on: project number / counts / supervisor / title questions are answered **deterministically from the data without calling Gemini**;
open topical questions call Gemini only when records explicitly support the question, every sentence must cite `[R#]` and is verified (invented titles,
years, names or numbers cause the generated text to be withheld and the verified record list to be returned). Questions the data cannot support
(e.g. "what were the study's results?" — the dataset holds bibliographic metadata only) return `status:"abstained"`.
If Gemini is down or misconfigured the call still returns HTTP 200 with the retrieved records and `status:"llm_unavailable"|"llm_error"`.

### Errors
`{"error":{"code","message","details":[],"request_id"}}` with HTTP 401 `unauthorized|token_expired`, 403 `forbidden`, 404 `*_not_found`,
409 `records_managed_externally|not_integrated_mode`, 422 `validation_error`, 503 `auth_not_configured`. `X-Request-ID` is returned on every response.

## 3. Gemini (generation) — separate from embeddings
* Config: `LLM_PROVIDER=gemini`, `LLM_API_KEY` (only in `.env`/secret store), `LLM_MODEL=gemini-3.8-flash|<supported Interactions model id>`.
  The embedding model (`EMBEDDING_BACKEND/EMBEDDING_MODEL`) is independent and was **not changed** (`paraphrase-multilingual-MiniLM-L12-v2`, matching the shipped `data/cache/embeddings.npz`).
* `python scripts/gemini_check.py` selects a model supported by the Interactions API and makes a real Arabic and a real English call through `POST /v1beta/interactions` (stateless `store=false`).
  It prints the exact model id to pin in `LLM_MODEL` for production. `auto` selects the newest **stable** `gemini-<ver>-flash[-lite]` (no preview/experimental).
* Privacy: `RAG_INCLUDE_STUDENTS=false` and `RAG_INCLUDE_SUPERVISORS=false` (defaults, set in `.env.example`) keep student and supervisor names out of every prompt; a test asserts it.
  Note the API itself still returns student/supervisor names to authenticated callers (needed for student/supervisor search); set `HIDE_STUDENT_NAMES=true` to remove student names from API responses too, or filter by role in your backend.
* Rotate the key if it was ever pasted into chat, email or a ticket.

## 4. Connecting the academy database (do not guess the schema — we need these answers)
The RAG never writes to your database. It reads one **read-only SQL view** with fixed column names:
`record_id, title, students, supervisors, year, call_number, extent, dimension, subjects`
(`students|supervisors|subjects` as `text[]` or `'|'`-separated text). Example and the Prisma mapping: `docs/INTEGRATION.md` §1, `integration/express/schema.sql`.

**Information required from the software team**
1. Database engine and version (PostgreSQL assumed; others need a SQLAlchemy driver) and network path from the RAG server (host, port, firewall/VPN).
2. The real table and column names for: project number/code, title, students, supervisors, year, call/classification number, pages (extent), dimension, subjects/specialisation → so the view can be written.
3. Confirmation that the project code is unique and never reused (it becomes `record_id`), including the 3 non-numeric codes (e.g. `ب908`).
4. A read-only database role (`rag_reader`) with `SELECT` on the view only → `SOURCE_DATABASE_URL=postgresql+psycopg://rag_reader:…@host:5432/db`.
5. How changes are announced (see below) and which roles may see student names.
6. Whether the RAG gets its own PostgreSQL database for its index (`DATABASE_URL`; SQLite file is fine for one server, PostgreSQL for several).

Set `RAG_MODE=integrated`, `SOURCE_DATABASE_URL`, `SOURCE_TABLE=rag_projects_v`, then run `POST /admin/sync` (or `python scripts/sync_from_source.py`) once to load.
In integrated mode your database is authoritative and `/admin/records` writes are refused (409).

**Making new/updated projects searchable (only changed rows are re-embedded; unchanged rows cost nothing):**
* Immediately: after your app commits a create/update/delete, call `POST /admin/sync/records/{record_id}` (admin token). Searchable within a second; deleted rows leave the index.
* Safety net: cron `*/5 * * * * cd /opt/sadat-rag && .venv/bin/python scripts/sync_from_source.py` (`--dry-run` shows what would change). Exit code 1 = problem.
* Check: `GET /admin/index/status`, `POST /admin/index/verify` (records vs embeddings vs in-memory indexes), `GET /admin/audit`.
* Standalone mode (no academy DB yet): `POST /admin/records`, `PUT|PATCH|DELETE /admin/records/{id}`, `POST /admin/import` (Excel, dry-run by default).
If an embedding cannot be computed the record is still saved and keyword-searchable, the embedding is retried (`POST /admin/index/reindex` with `pending`).

## 5. Production checklist
`SERVICE_JWT_SECRET` ≥ 32 random chars · `AUTH_DISABLED=false` · `LLM_API_KEY` only in secrets · HTTPS reverse proxy in front · keep `--no-access-log`
(access logs would contain query text) · persist `data/store` (volume) · restrict who can reach `/admin/*` · `data/raw/Project.xlsx` contains real student names: store it privately.
